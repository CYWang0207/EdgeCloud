# 接口契约 v0（草稿 · 待阶段 0 碰头会冻结）

> **接口先行**是集成不翻车的前提。本文档由队长牵头，东方组与周组共同拍板后冻结为 v1。
> 对应《整体规划》中的三个技术闭环点。

---

## 闭环点 ① A → B：预测器即代价模型

**模块 A 提供：**

| 项 | 内容 | 格式（待定） |
|---|---|---|
| SubNet 查找表 | `{SubNet_id → (TTFT, mem, acc_surrogate)}` | JSON / CSV（待定） |
| 可执行权重 | 每个 SubNet 变体的 NCNN / FP16 权重 | 文件路径约定（待定） |
| 切换接口 | 按 `SubNet_id` 运行时热切换 | Python API 签名（待定） |

**模块 B 消费方式：** 将 `{v_t, k_t}` 决策映射到 SubNet 变体空间的一个操作点，
直接以 LUT 中的标签作为 `Cost_comp(k_t, v_t)` 与 `Accuracy(k_t, v_t)` 的真实代价/效用模型。

**待定项：**
- [ ] `{v_t, k_t} → SubNet_id` 的映射规则
- [ ] LUT 字段单位（TTFT: ms? 内存: MB?）与精度代理的定义
- [ ] 切换时延上限约定

---

## 闭环点 ② C → A → 边侧：更新即再编译

| 触发 | 下发内容 | 约束 |
|---|---|---|
| `u_t = 1`（环境更新） | 轻量 Penv + ωt，不回传权重 | 上行开销极低 |
| `u_t = 2`（重训练） | Replay Buffer 持续学习 / DoRA 微调 → **重过 AutoTailor 流水线** → 权重差量 | 下发变体必须仍满足 TTFT / 内存约束 |

**待定项：**
- [ ] Penv / ωt 的数据结构与序列化格式
- [ ] 权重差量的打包格式与热更新协议
- [ ] 再编译触发方式（API / 消息队列 / 手动）

---

## 闭环点 ③ 全局 ↔ 局部：多节点一致性仲裁（新增 ★）

**模块 C 提供：** 云端基于跨节点全局上下文的冲突检测 + 一致化决策下发。
**边侧（模块 B）提供：** 冲突回滚机制。

**待定项：**
- [ ] 节点上报的上下文格式（重叠区域标识、本地决策摘要）
- [ ] 仲裁结果的下发格式与生效时序
- [ ] 回滚触发条件与状态恢复方式

---

## 修改流程

1. 提议人在本文档对应小节写明变更 + 理由，提 PR
2. 接口相关方（东方组成员 2 / 周组成员 2、3 / 队长）评审通过后合并
3. `common/` 中的对应实现同步更新
