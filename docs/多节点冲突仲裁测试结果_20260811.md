## ① 多节点冲突仲裁评估

### 一句话结论

BoxCars116k 官方 test 全量 **12,322 样本 × 4 节点**（各看 3/4 视角）实测：
**冲突率 4.06% ≤ 5% ✅、解决率 100% ≥ 90% ✅**，weighted 与 bayesian 两种融合策略均达标。

### 结果（全量 test）

| 指标 | Weighted（加权投票） | Bayesian（贝叶斯融合） | 硬指标 |
|---|---|---|---|
| 冲突率 | **4.06%**（500/12,322） | **4.06%**（500/12,322，完全一致） | ≤5% ✅ |
| 解决率 | **100.00%** | **100.00%** | ≥90% ✅ |
| 回滚数 | 661 | 729 | — |

- 冲突数都是 500：**冲突检测与融合策略无关**，区别只在仲裁细节——bayesian 对部分样本选了不同 final_pred，多纠正 68 个节点（回滚 729 vs 661），解决率同为 100%。
- 冒烟验证：`--max-samples 100` 通过（0 冲突）；50 条通过。
- 冲突样本仲裁正确率 55.40% 与多数投票 55.60% 持平 → 仲裁无偏差。

### 原始失败归因（markov，248 个业务不可用时隙）

```text
biz_fail=248  全部 conf<0.8（acc_floor=0.8 打掉）
  其中 决策错误: 106（且 conf≥0.8，即"高置信但错"）
        断联期间: 17
        e2e 超时: 0   transmission 失败: 0
按 u：conf<0.8 时隙 u=0 占 136、u=1 占 112
裁剪量：conf<0.8 时隙 avg_token_sum=0.471 vs 正常时隙 0.469（几乎相同）
```

### 归因结论与建议（重要）

1. **adapter 在干净数据上是净负作用**：u=1 分支（cloud-unlabeled adapter）在 clean test 上准确率 87.89%，低于 u=0 的 base 93.10% 达 5.2pp。B 实验证明：**u=1 时隙换回 base 后，acc_floor=0.8 原门槛下业务保持率即达 91.17% 过线**。
2. **真正的病根是调度选错了 u**：轨迹全为低漂移（normal）样本，但调度仍选了 32.5% 的 u=1（理想应几乎全 u=0 本地自治省钱）。B 实验用"u=1 也走 base"绕开该问题，揭示的正解是**让调度只在真漂移时才选 u=1**。
3. **裁剪不是元凶**：E3 强制 4 视角全开，准确率不升反降（90.32%），且低/高置信度时隙的 token 保留几乎相同 → 信息裁剪已接近调度权衡合理点。
4. 248 个失败时隙全部因 conf<0.8 被 acc_floor 打掉，无一因 e2e 超时/传输失败 → 瓶颈在感知置信度（根因是 1+2），不在网络/时延。

**三条验证过的修复路径（全部过线）**：

| 方案 | 业务保持率 | 特点 |
|---|---|---|
| A：acc_floor 0.8→0.7 | 92.10–92.71%（四档全过） | 最简单，纯参数；但"放宽门槛"需答辩解释，且要和唐凤玲对齐口径 |
| B：u=1 低漂移时走 base / 调度少选 u=1 | 91.17%（markov） | 不动判据、答辩叙事最漂亮（"调度会判断何时找云端"）；需修调度策略或 adapter 训练 |
| E3：强制 4 视角 | 91.37% | 不碰判据，但准确率反降、带宽多，不推荐 |

**建议方向**：B 指出的方向（按漂移选 u，低漂移不触发 u=1）最值得做——既是根因修复，答辩还加分；实现需动 Actor 策略/候选生成或重训 adapter（张晨侧）。A 为最快备选交付方案。

## 诚实边界（答辩口径）

- 多节点部分：4 视角非 4 物理摄像头（BoxCars 同摄像头 4 时间观测）；4 节点看同一样本非多路口多目标；target_id=样本序号非 ReID。
- 全链路部分：T_edge=80ms 沿用模拟版写死口径（未含真实通信负载 e2e）；u=2 重训分支未提供权重（回退 u=1）；轨迹全为 low-drift（normal）样本，未见真漂移场景下的 u=1 增益。
- 业务保持率原始 89.67–89.95% 未达 90%，根因已定位（adapter 干净数据负作用 + 调度过选 u=1），三条修复路径已验证过线，方案待团队拍板。
