## ① 多节点冲突仲裁评估（要求 1）

### 一句话结论

BoxCars116k 官方 test 全量 **12,322 样本 × 4 节点**（各看 3/4 视角）实测：
**冲突率 4.06% ≤ 5% ✅、解决率 100% ≥ 90% ✅**，weighted 与 bayesian 两种融合策略均达标。

### 实验设置

| 项目 | 值 |
|---|---|
| 运行分支 | `feat/multinode-test`（代码 rsync 至 `~/autodl-tmp/EdgeCloudRuntime/worktrees/multinode-test/`） |
| 运行环境 | a3 AutoDL：RTX 3090（24GB），torch 2.8.0+cu128，bf16 autocast |
| 评估集 | BoxCars116k 官方 test 全量 12,322 样本，16 类品牌（make） |
| 数据路径 | `shared/data/BoxCars116k_kaggle/BoxCars116k` |
| 模型 | 4 节点共用 MV-ViT-S baseline（`shared/checkpoints/boxcars_make_baseline/best.pth`）+ 8/9 cloud-teacher adapter（`worktrees/adjust/checkpoints/internvit6b_cloud_teacher_adapter_20260809/cloud_unlabeled/best.pth`） |
| 视角分配 | 各看 3 视角缺 1：`[1110][1101][1011][0111]` |
| 冲突判定 | 同 target 多节点 + 预测不一 + 双方 conf>0.7 |
| 主脚本 | `module_scheduling/multi_node/multi_node_eval.py` |

### 结果（全量 test）

| 指标 | Weighted（加权投票） | Bayesian（贝叶斯融合） | 硬指标 |
|---|---|---|---|
| 冲突率 | **4.06%**（500/12,322） | **4.06%**（500/12,322，完全一致） | ≤5% ✅ |
| 解决率 | **100.00%** | **100.00%** | ≥90% ✅ |
| 回滚数 | 661 | 729 | — |

- 冲突数都是 500：**冲突检测与融合策略无关**（同一批 disagreements），区别只在仲裁细节——bayesian 对部分样本选了不同 final_pred，多纠正了 68 个节点（回滚 729 vs 661），解决率同为 100%。
- 冒烟验证：`--max-samples 100` 通过（0 冲突）；`--max-samples 50` 通过。
- 冲突样本仲裁正确率 55.40% 与多数投票 55.60% 持平 → 仲裁无偏差；冲突样本本质是"节点预测分歧"的困难样本。

### adapter 加载验证（队友要求的核对项）

```text
baseline 主干加载: missing=0, unexpected=0
adapter 权重加载: missing=156, unexpected=0
adapter 权重 key 数: 60  →  key 命中且数值一致: 60  数值不一致: 0  模型里找不到: 0
adapter 参数: total=299,916  abs_mean=0.0150  abs_max=1.0379（非零，非零初始化占位）
```

结论：**cloud-teacher adapter 可被 `load_adapter_checkpoint` 直接加载**。missing=156 是"模型里不属于 adapter 的冻结参数"（主干/head/norm），adapter-only checkpoint 的正常现象；unexpected=0 且 60 个 key 全部命中数值一致，加载正确。此结论同样适用于要求 2 的 `main_edge_cloud_real_model.py`（同一套加载逻辑）。

## ② 主循环 + 真模型 + adapter + network_sim 全链路闭环（要求 2，ModelNet40）

### 一句话结论

`main_edge_cloud_real_model.py`（PR #37）一次跑通，无接口问题。四档网络模式全量（2,468 时隙）：
**e2e 达标率 100%（avg/P95 = 80ms）✅；业务保持率 89.67%–89.95%，差 0.05–0.33% 未达 90% ⚠️**。
真模型策略准确率 91.21%–91.41%，低于全视角轨迹基线 96.76%（差约 5.4%）。

### 实验设置

| 项目 | 值 |
|---|---|
| 轨迹 | `shared/trajectories/trajectory_20260810/trajectory_modelnet40.csv`（2,468 时隙） |
| 数据 | `shared/data/modelnet40v2png_ori4`（40 类） |
| baseline | `shared/checkpoints/mv_vit_token_epoch_30.pth`（missing=0, unexpected=0） |
| adapter | `worktrees/adjust/outputs/modelnet40_cloud_delivery_20260809/cloud_unlabeled_adapter.pth`（u=1 加载：missing=156, unexpected=0） |
| 调度/网络 | 复用 `main_edge_cloud_new` 参数（b_avg=3.0, V=20.0, deadline=200ms, acc_floor=0.8, T_edge=80ms 写死口径） |

### 结果（四档 × 全量 2,468 时隙）

| 网络模式 | 业务保持率 | e2e 达标率 | avg/P95 e2e | 断联率 | 真模型策略准确率 | u 分布（0/1/2） |
|---|---|---|---|---|---|---|
| static | 89.67% | 100.00% | 80.0/80.0ms | 0.00% | 91.21% | 66.4% / 33.6% / 0% |
| jitter | 89.67% | 100.00% | 80.0/80.0ms | 0.00% | 91.21% | 66.4% / 33.6% / 0% |
| jitter_outage | 89.67% | 100.00% | 80.0/80.0ms | 0.00% | 91.21% | 66.4% / 33.6% / 0% |

- 冒烟 100 时隙通过（markov，业务保持率 99%）。
- 真模型平均置信度 0.946–0.948；平均激活视角 3.005/4；平均 token 保留率总和 0.469。

### 业务保持率未达 90% 的归因（重要 ⚠️）

markov 档 248 个业务不可用时隙（89.95% 对应失败 248/2,468）归因：

```text
biz_fail=248  全部 conf<0.8（acc_floor=0.8 打掉）
  其中 决策错误: 106（且 conf≥0.8，即"高置信但错"）
        断联期间: 17
        e2e 超时: 0   transmission 失败: 0
```

按 u 分组的准确率与业务保持率：

| u | n | 准确率 | 平均 conf | 业务保持率 |
|---|---|---|---|---|
| u=0（base 无 adapter） | 1,667 | **93.10%** | 0.958 | 91.84% |
| u=1（cloud-unlabeled adapter） | 801 | **87.89%** | 0.927 | 86.02% |

**关键观察（需队友确认口径/权重）**：
1. **u=1 分支反而更差**：clean test 上 cloud-unlabeled adapter（87.89%）比无 adapter 的 base（93.10%）低 5.2pp，把整体业务保持率拖到 90% 以下。adapter 是为漂移数据训练的，在 clean 数据上可能轻微负作用（BoxCars 的 cloud-teacher 有 "clean 94.61% 不退化" 记录，ModelNet 侧需对齐验证）。
2. 248 个失败全部因 conf<0.8 被 acc_floor 打掉，无一因 e2e 超时/传输失败 → 业务可用性瓶颈在感知置信度而非网络/时延。
3. 断联时强制 u=0，markov 断联率 6.12% 下业务保持率反而最高（89.95%），因为 u=0 分支准确率更高。
4. `jitter_outage` 默认参数未启用断联（disconnect_prob=0/outage_period=0），故与 jitter 完全一致；如需真断联场景应加 `--disconnect-prob/--outage-period`。

## 诚实边界（答辩口径）

- 多节点部分：4 视角非 4 物理摄像头（BoxCars 同摄像头 4 时间观测）；4 节点看同一样本非多路口多目标；target_id=样本序号非 ReID。
- 全链路部分：T_edge=80ms 沿用模拟版写死口径（未含真实通信负载 e2e）；u=2 重训分支未提供权重（回退 u=1）；jitter_outage 默认未开断联参数。
- 业务保持率 89.67–89.95% 未达 90%，结论尚不能作为"达标"交付，需按归因结论调整（见上）。
