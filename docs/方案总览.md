# 方案总览：面向端边云协同推理的分布式感知与全局优化决策系统

## 赛题理解

赛题要求构建一套"分布式感知 + 云边协同推理 + 全局优化决策"系统。当前核心判断是：**云端大型视觉基础模型不进入边缘 forward，而是在云端把更鲁棒的视觉表征压缩为轻量 AdaptFormer 参数，下发到边缘 ViT 旁路。** Qwen3-VL condition 路线已作为消融归档；正式定义见[云端视觉教师 Adapter 刷新方案](云端视觉教师Adapter方案_20260809.md)。

## 系统闭环

```
感知（边缘 MV-ViT 多视角推理，主干冻结 + AdaptFormer adapter 可训练）
  -> 漂移检测（香农熵 Edrift + 结构性漂移 struct_drift）
  -> 调度（Actor-Critic 在线决策 {vt, ut, kt}）
  -> 协同（ut=1 下发 adapter 参数几百KB~MB 治环境漂移；ut=2 下发重训权重 ~50MB 治结构性漂移；ut=0 本地自治）
  -> 云端视觉教师持续刷新 adapter + 多节点仲裁
  -> 回到感知
```

## 模块划分

### 模块一：边缘实时感知（module_edge_perception）
- MV-ViT 多视角推理（ViT-Small，2200万参数，主干冻结）
- AdaptFormer adapter：挂每个 Transformer block 的 FFN 旁路并行，r=32，W_up 零初始化，可训参 <1M（知识压缩的载体）
- Token 剪枝：动态保留率 k_t，降低 Self-Attention 复杂度
- 漂移模拟：5种环境漂移（变亮/暗/模糊/噪声/遮挡）+ 结构性漂移分数
- Prompt / VLM condition：旧方案，已归档为消融，不进入正式 edge forward
- 性能测量：TTFT、推理延迟、GPU 内存

### 模块二：云边协同调度（module_scheduling）
- Actor-Critic RL：Actor（DNN）生成候选动作，Critic（注水算法）精确评估
- Lyapunov 带宽队列：长期平均带宽约束
- Cloud Visual Teacher：冻结视觉基础模型输出 task logits/features，云端训练 adapter
- 多节点协同：冲突检测（<5%）+ 一致性仲裁（>90%）
- 网络韧性：带宽波动 + 断连 fallback（已实现，network_sim 已接入主循环）

## 知识压缩方案（答辩核心）

传统思路：全量大模型 -> 剪枝/量化/蒸馏 -> 小模型 -> 边缘部署
我们的思路：云端冻结视觉基础模型 -> 对漂移关键帧产 task logits/features -> 云端蒸馏压缩进 AdaptFormer adapter(约 1.2MB) -> 下发到边缘 ViT 旁路

**压缩的不是参数，是云端大模型蒸馏出来的场景知识；传输的不是模型，是这个压缩后的小适配器。** 比"把 DeepSeek 量化蒸馏成迷你模型部署边缘"更可行（大模型再压缩也跑不动毫秒级多视角融合），比"纯 Prompt 注入"更贴赛题"基于全量大模型压缩"字面、且能力保持率可测。

## 技术指标达成路径

| 指标 | 如何达成 |
|------|---------|
| 边侧参数量千万级 | ViT-Small（2200万）天然满足 |
| 边侧能力保持 80-90% | 以 cloud visual teacher 的漂移域表征监督 Adapter，并以四类退化表实测 |
| TTFT降低 >= 75% | Token 剪枝：序列长度从785 -> 200，Attention O(N^2) 降低90%+ |
| 内存 <= 1.5GB | ViT-Small + Token剪枝约1GB |
| 端到端 <= 0.2s | 视角休眠 + Token剪枝 + 注水算法O(V^2) |
| 业务连续性 >= 90% | Lyapunov 稳定性 + ut=0 本地自治 |
| 冲突 <= 5%，解决 >= 90% | 云端全局仲裁 + 置信度加权投票；VLM 只可作高层结构漂移辅助 |
| >= 2类场景 | ModelNet40（场景一）+ BoxCars116k 车辆品牌识别（场景二，baseline 88.04%） |
