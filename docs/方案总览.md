# 方案总览：面向端边云协同推理的分布式感知与全局优化决策系统

## 赛题理解

赛题要求构建一套"分布式感知 + 云边协同推理 + 全局优化决策"系统。当前正式方案为 **cloud-teacher（云端视觉教师 Adapter）**：云端冻结 InternViT-6B（国产开源视觉大模型，5.9B 参数）作为教师，在独立离线标注集上训练场景分类头，再对代表性漂移样本生成 `{features, logits}` 教师监督；边缘 AdaptFormer 在**不使用上传样本真实标签**的条件下蒸馏训练，产出约 1.2MB 的 adapter-only checkpoint 下发。边缘 forward 只跑 MV-ViT-S + Adapter，不含大模型，不依赖云端实时返回。原 FiLM/VLM-conditioned 方案因对低层相机漂移无可靠增益，已降级为消融实验。方法定义与实验总览见[实验结果总览](实验结果总览_20260809.md)。

## 系统闭环

```
感知（边缘 MV-ViT 多视角推理，主干冻结 + AdaptFormer adapter 可训练）
  -> 漂移检测（香农熵 Edrift + 结构性漂移 struct_drift）
  -> 调度（Actor-Critic 在线决策 {v_t, u_t, k_t}）+ 多节点仲裁
  -> 协同：
       u=0 本地自治，离线/弱网可用；
       u=1 cloud-teacher adapter refresh：
           上传漂移样本（无标签）→ 云端 InternViT-6B 提取 {features, logits}
           写入 Teacher Cache → 四目标蒸馏更新约 0.3M 参数，
           投影头 P 不下发，导出约 1.2MB best.pth → 下发边缘热加载，
           Forward 不含大模型，不依赖云端实时返回；
       u=2 结构性漂移/任务变化，更新主干或分类头等更大范围模型，
           异步后台进 Q_net 跨槽消化
  -> 回到感知
```

## 模块划分

### 模块一：边缘实时感知（module_edge_perception）
- MV-ViT 多视角推理（ViT-Small，2200万参数，主干冻结）
- AdaptFormer adapter：挂每个 Transformer block 的 FFN 旁路并行，r=32，W_up 零初始化，约 0.300M adapter 参数（cloud-teacher 蒸馏载体）
- Token 剪枝：动态保留率 k_t，降低 Self-Attention 复杂度
- 漂移模拟：校准后的合成相机漂移（illumination / motion_blur / defocus / sensor_noise，每场景 3 类固定强度）+ 结构性漂移分数
- Prompt/VLM 条件注入：历史消融方案，已不作为正式推理链路
- 性能测量：TTFT、推理延迟、GPU 内存

### 模块二：云边协同调度（module_scheduling）
- Actor-Critic RL：Actor（DNN）生成候选动作，Critic（注水算法）精确评估
- Lyapunov 带宽队列：长期平均带宽约束
- 云端教师缓存：云端冻结 InternViT-6B，离线提取代表性漂移样本的视觉特征与分类 Logits 并写入 Teacher Cache，供后续 Adapter 蒸馏训练使用
- 多节点协同：冲突检测（实测 4.06% ≤5%）+ 一致性仲裁（实测 100% ≥90%）
- 网络韧性：带宽波动 + 断连 fallback（已实现，network_sim 已接入主循环）

## 知识压缩方案（答辩核心）

传统思路：全量大模型 -> 剪枝/量化/蒸馏 -> 小模型 -> 边缘部署

我们的思路：云端冻结视觉基础模型 -> 对漂移关键帧产 task logits/features -> 云端蒸馏压缩进 AdaptFormer adapter（约 1.2MB）-> 下发到边缘 ViT 旁路

**压缩的不是参数，是云端大模型蒸馏出来的场景知识；传输的不是模型，是这个压缩后的小适配器。** 比"把 DeepSeek 量化蒸馏成迷你模型部署边缘"更可行（大模型再压缩也跑不动毫秒级多视角融合），比"纯 Prompt 注入"更贴赛题"基于全量大模型压缩"字面、且能力保持率可测。

```text
场景数据 -> 漂移样本（无标签）-> 云端 InternViT-6B 提取 {features, logits}
         -> 写入 Teacher Cache -> 蒸馏训练 AdaptFormer（约 0.3M 参数）
         -> 投影头 P 不下发 -> adapter-only checkpoint（约 1.2MB）
         -> 边缘热加载（Forward 完全不含大模型，离线实时推理）
```

蒸馏训练由四个目标联合驱动：(1) 离线标注集分类——保留原始标注数据的分类监督，防止云端模型预测偏差主导训练，此监督来自预先标注的训练集而非边缘上传样本；(2) 云端预测迁移——以云端模型对漂移样本的类别预测为参考，将云端模型的场景判别能力压缩进 adapter；(3) 特征空间对齐——通过云端训练的投影头 P，保持边缘与云端对同一样本的特征表示一致，投影头不下发至边缘；(4) Clean 能力保持——对干净样本约束 adapter 输出不偏离冻结 baseline，确保漂移适配不会牺牲原始场景的识别精度。两场景使用各自的云端模型与 adapter 权重，不跨场景复用。正式 cloud-unlabeled 方案设 λ_CE=0，即不启用 CE 目标；CE 仅在 label-only 有标签上界对照中激活。

## 技术指标达成路径

| 指标 | 如何达成 |
|------|---------|
| 边侧参数量千万级 | ViT-Small（2200万） |
| 边侧能力保持 80-90% | 云端 InternViT-6B 提供教师监督，adapter 蒸馏后在漂移条件下恢复边缘识别精度 |
| TTFT降低 >= 75% | Token 剪枝：序列长度从785 -> 200，Attention O(N^2) 降低90%+ |
| 内存 <= 1.5GB | ViT-Small + Token剪枝，实测 0.08GB |
| 端到端 <= 0.2s | 视角休眠 + Token剪枝 + 注水算法O(V^2) |
| 业务连续性 >= 90% | Lyapunov 稳定性 + ut=0 本地自治 |
| 冲突 <= 5%，解决 >= 90% | 云端全局仲裁 + 置信度加权投票 |
| >= 2类场景 | ModelNet40（场景一）+ BoxCars116k 车辆品牌识别（场景二，baseline 88.04%） |
