# BoxCars 云端视觉教师实验：状态、证据与边界

> 本文是当前 `adjust` worktree 的实验说明。它把“已验证的开发集结果”“已完成的独立 test 检查”和“尚未证明的系统能力”分开写，避免把原型结果说成最终结论。

## 一句话结论

目前证据支持这样一个较窄、但真实的结论：在 BoxCars 的 illumination、motion blur、sensor noise 相机退化上，冻结的云端 `InternViT-6B` 加任务头可以为**没有人工标签的上传漂移样本**提供足够有效的监督，使云端训练出的约 1.2 MB `AdaptFormer` 更新包把边缘 MV-ViT-S 的开发集平均漂移准确率从 81.97% 提升到 85.21%。

这不等价于“云端 teacher 在已有真实标签时总能提升 Adapter”，也不等价于“系统已经在全量官方 test 和真实网络链路上完成最终验收”。

## 为什么不再使用 VLM-conditioned Adapter

旧路线让 Qwen3-VL 的语义 hidden state 或 condition 直接调制 edge Adapter。它的职责与问题不匹配：

```text
本项目漂移：illumination / blur / sensor noise
本质：低层 camera covariate shift

Qwen3-VL 的主要能力：语义、物体、文本、关系和语言推理
```

在细粒度 BoxCars 品牌识别中，旧 Qwen3-VL teacher 的 clean 准确率仅为 62.25%，而 Edge baseline 的既有官方 clean test 为 88.04%。更重要的是，旧 condition 对 drift correction 没有可靠增益。因此旧路线被保留为**负向消融**，实现和记录归档在 `local/archive/`，不再进入当前 edge forward。

## 当前正式机制

```text
边缘检测到环境漂移
  -> 上传少量 representative / hard 四视图轨迹
  -> 云端冻结 InternViT-6B 提取视觉 feature
  -> 已训练的 BoxCars task head 产生 16 类 logits
  -> 云端只优化 MV-ViT-S 的 AdaptFormer
  -> 下发 adapter-only checkpoint
  -> 边缘 MV-ViT-S + Adapter 恢复推理
```

云端模型不在边缘推理图中；边缘也不需要等待一个 128D VLM condition。`u=1` 只在需要刷新时使用云端，刷新完成后 edge 继续本地运行。

### 三个调度动作的含义

| 动作 | 当前定义 | 用途 |
|---|---|---|
| `u=0` | 当前 Edge + 已有 Adapter 本地自治 | 无漂移、弱网或云端不可用 |
| `u=1` | cloud teacher-guided Adapter refresh | 环境漂移；上传少量代表样本，更新 Adapter |
| `u=2` | 更大范围的结构性模型更新 | 类别、任务或场景结构发生变化 |

## 训练对象和损失

冻结的 InternViT-6B 只做 feature extraction；不微调、不 LoRA。其 3,200 维 track feature 经过 BoxCars 任务 head 得到 teacher logits。边缘 MV-ViT-S backbone、norm、分类头均冻结，只训练每层 FFN 旁路中的 AdaptFormer；feature projector 只在云端训练期存在，不进入下发物。

对于漂移样本，学生输出为 `(z_S, h_S)`，teacher 输出为 `(z_T, h_T)`；clean replay 中关闭 Adapter 的 baseline logits 为 `z_0`：

\[
L = \lambda_{CE} L_{CE}(z_S,y)
  + \lambda_{KD} KL_T(z_S,z_T)
  + \lambda_f [1-\cos(P(h_S),h_T)]
  + \lambda_a KL_T(z_S^{clean},z_0).
\]

部署语义正确的 cloud-unlabeled 版本设定 `λ_CE=0`：上传样本没有人工标签，teacher 取代标签；KD、feature alignment 和 clean anchor 保持。`label-only` 仅是“如果上传样本恰好有人标注”的监督上界。`hybrid` 是把 CE 和 teacher 项同时使用的消融，不是主系统。

## 已完成的开发集证据

head 选择和 Adapter checkpoint 选择均在 validation 上完成，所以本表只能称为**开发集**结果。

| 模型 | Clean | Illumination 1.0 | Motion blur 0.8 | Sensor noise 0.6 | 漂移平均 |
|---|---:|---:|---:|---:|---:|
| Edge baseline | 93.84% | 81.82% | 84.59% | 79.51% | 81.97% |
| InternViT-6B + selected task head | 96.15% | 94.92% | 91.99% | 82.59% | 89.83% |
| label-only Adapter（有标签上界） | 94.30% | 83.05% | 87.52% | 87.67% | 86.08% |
| cloud hybrid Adapter（消融） | 94.30% | 83.36% | 86.75% | 86.90% | 85.67% |
| cloud-unlabeled Adapter（正式 u=1） | 94.61% | 83.05% | 86.13% | 86.44% | 85.21% |

由此得到的严格解读是：

- teacher 在三种开发漂移条件下均优于 Edge，尤其先前薄弱的 noise 也为 82.59% > 79.51%；
- 无标签 cloud refresh 相对 Edge 的漂移平均提升 **3.24 pp**；与 label-only 上界相差 **0.87 pp**；
- cloud-unlabeled 的 clean 与三种漂移均未低于 Edge；
- hybrid 比 label-only 低 **0.41 pp**，所以不能宣称“teacher + CE 一定优于 CE”。

## 为何 noise head 是必要修正

第一个 mixed-drift linear head 在 noise 上只有 73.19%，不能担任三漂移 teacher。没有跳过这个问题，而是在已存在的 train feature cache 上比较了 general linear、noise-weighted linear、noise specialist 和 noise-weighted MLP。最后的 `noise_weighted_mlp` 同时满足 clean ≥ 92.8%、noise ≥ 79.5% 的准入门槛，才被固定为 `selected_head.pt`。

这一步是**训练任务 head**，不是微调 6B backbone；它让大视觉模型获得 BoxCars 的品牌分类对齐能力，也避免直接拿通用视觉 feature 或 VLM 品牌 logits 做不可靠蒸馏。

## 已验证的工程约束

| 项目 | 已验证事实 |
|---|---|
| 云端 teacher | `OpenGVLab/InternViT-6B-224px`，冻结、BF16、仅云端离线/刷新期使用 |
| Edge 模型 | `EarlyFusionMultiViewViT(vit_small_patch16_224)`，4 个逻辑视图 |
| Adapter | `r=32` 的 AdaptFormer，299,916 参数 |
| 下发大小 | 实测 `1,216,745 bytes`，约 1.2 MB |
| 下发内容 | 仅 Adapter 参数；不含 backbone、norm、head、teacher 或训练期 projector |
| 数据对齐 | teacher cache 保存原始 index、drift type、severity；训练时逐 batch 校验 |
| clean 保持 | anchor 将“开启 Adapter 的 clean replay”与“关闭 Adapter 的冻结 baseline”对齐 |

## 独立 test 的快速检查

官方 BoxCars `test` split 有 12,322 条，类别高度不均衡；其中 Porsche 仅 3 条。为了不把长时间全量 6B 推理伪装成“快速验证”，本轮使用固定 seed 的 256 条 class-stratified test 子集：每类至少一条，其余按官方 test 类别容量比例分配。固定 checkpoint 只评估：

1. Edge baseline；
2. cloud-unlabeled Adapter；
3. InternViT-6B + 已固定的 `selected_head.pt`。

固定条件为 clean、illumination=1.0、motion blur=0.8、sensor noise=0.6。评估器保存 exact sample indices、每条预测和 Edge/Adapter 的 paired bootstrap 区间。其产物位于：

```text
module_edge_perception/evaluate_boxcars_cloud_teacher_quick_test.py
outputs/internvit6b_cloud_teacher_quick_test_20260809/
```

实际结果如下；运行时间为 288 秒，Edge、Adapter 和 teacher 使用同一组样本、同一套 corruption seed：

| 模型 | Clean | Illumination | Motion blur | Sensor noise | 漂移平均 |
|---|---:|---:|---:|---:|---:|
| Edge baseline | 85.55% | 74.61% | 73.83% | 69.92% | 72.79% |
| cloud-unlabeled Adapter | **87.50%** | **76.17%** | **74.22%** | **77.73%** | **76.04%** |
| InternViT-6B teacher | 92.97% | 91.41% | 91.02% | 80.86% | 87.76% |

这给出三个直接事实：

- teacher 仍明显强于 Edge（平均漂移高 14.97 pp），故它有资格承担云端监督；
- 无标签 Adapter 的平均漂移提高 **3.26 pp**，clean 也提高 **1.95 pp**，与开发集的方向一致；
- 改善主要来自 noise：Edge→Adapter 为 +7.81 pp，2,000 次配对 bootstrap 的 95% CI 是
  `[+3.91, +11.72] pp`。illumination +1.56 pp、blur +0.39 pp 的小幅差异在 256 条样本上 CI
  仍跨 0，因此不宣称它们单独已达到强统计显著。

该检查的正确定位是“独立 split 上的快速方向确认”。它已经足以继续做 demo/系统接入；若用于最终论文式主张，仍应在不改 checkpoint 的前提下补一次全量 test。

## 当前不做什么

- 不下载 DINOv3：InternViT 已在当前三类漂移开发集上通过 teacher gate；DINOv3 只有在当前 teacher 失败时才是替代项。
- 不微调 / LoRA InternViT：当前证据并未显示 teacher 容量不足，瓶颈不在此处。
- 不继续调 hybrid：它已经回答“有标签 CE 上叠加现有 teacher loss 无额外收益”。
- 不恢复 Qwen3-VL condition：旧实验已经否定了它对低层 drift correction 的职责分配。
- 不默认做全量 13,098 条 Adapter 训练：它不符合“u=1 上传少量代表样本”的系统设定。

## 最小且务实的后续口径

本轮快速 test 结束后，不需要立刻机械追加多 seed、四档预算或全套 loss 消融。只需：

1. 如果快速 test 与开发集方向一致，把 cloud-unlabeled checkpoint 接到 `u=1` demo，记录上传样本数、刷新耗时与 1.2 MB 下行包；
2. 在写最终报告或需要强统计结论前，再补全量 official test；
3. 只有当独立 test 失败时，才回查 head 过拟合、代表样本选择或 cache 对齐，而不是立刻换 DINO 或回到 VLM condition。
