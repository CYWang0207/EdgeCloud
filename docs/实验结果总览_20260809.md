# 实验结果总览：两类场景的 cloud visual teacher 闭环验证

> 本文是 2026-08-09/08-10 云端 `adjust` 分支实际运行结果的总体说明。两个数据集各有一份结果文档：
> [`第一场景_ModelNet40.md`](第一场景_ModelNet40.md) 与 [`第二场景_BoxCars116k.md`](第二场景_BoxCars116k.md)。
> 方法的完整设计说明已归档至 `local/archive/status_docs_20260810/云端视觉教师Adapter方案_20260809.md`，
> 要点摘在下文"方法"一节。

## 一句话结论

冻结的云端视觉基础模型 `InternViT-6B` 不必进入边缘 forward，只对漂移代表轨迹输出 task
logits / visual features；云端用这些监督训练约 0.3M 参数的 AdaptFormer，并向边缘下发约 1.2 MB
更新包，使冻结的边缘 MV-ViT-S 在两类数据集、多类相机退化上恢复能力。BoxCars 与 ModelNet40
独立验证均支持该闭环。

## 方法（两场景共用）

```text
漂移检测 → 上传少量 representative / hard 四视图轨迹
  → 云端冻结 InternViT-6B 提取 task logits + visual features
  → 云端只训练 MV-ViT-S 的 AdaptFormer（约 0.3M 参数）
  → 下发 adapter-only checkpoint（实测 1,216,745 bytes，约 1.2 MB）
  → 边缘 MV-ViT-S + Adapter 低延迟恢复推理（断网时 u=0 本地自治）
```

云端训练目标对同一轨迹的漂移输入 \(x_d\)，teacher 输出 logits \(z_T\) 与特征 \(h_T\)；开启 Adapter
的学生输出 \(z_S,h_S\)，关闭 Adapter 的冻结 baseline 对 clean replay 输出 \(z_0\)：

\[
L = L_{CE}(z_S,y) + \lambda_{KD} KL_T(z_S,z_T) + \lambda_f[1-\cos(P(h_S),h_T)] + \lambda_a KL_T(z_S,z_0)
\]

- **CE**：真实标签监督（离线阶段，用于 task head 和 label-only 上界）。
- **KD**：迁移 teacher 在漂移样本上的任务判别分布。
- **feature alignment**：通过只在云端训练期存在的投影器 `P` 对齐视觉表征，`P` 不下发。
- **anchor**：clean replay 防止 Adapter 只适应当前漂移而损伤原始能力。
- 正式 **cloud-unlabeled refresh** 设 \(\lambda_{CE}=0\)：上传漂移样本没有人工标签，teacher 取代标签；
  `label-only` 是"如果恰好有标注"的监督上界，`hybrid` 是同时使用 CE 的消融，都不是主系统。

调度语义（与 `接口契约.md` 一致）：`u=0` 本地自治；`u=1` cloud-teacher 指导的 Adapter refresh
（本方案主链路）；`u=2` 结构性模型更新（换主干/分类头）。大模型、task head、cache、训练期
projector 永远留在云端，不进入边缘 forward，也不随 adapter 下发。

该方法取代旧的 Qwen3-VL condition / 品牌 soft-label 路线——后者被保留为负向消融
（`local/archive/vlm_conditioned_20260809/`），不恢复。

## 相同方法、两套协议

两个数据集使用同一方法（冻结 6B → 训练任务头 → dev 上过 teacher gate → 无标签 refresh 训练
Adapter → 固定 checkpoint 后评估），协议严格程度不同：

| 项目 | ModelNet40（场景一） | BoxCars116k（场景二） |
|---|---|---|
| 类别 | 40 类 | 16 类品牌 |
| 视角 | 4 视图，逐视角分类后平均 track logits | 4 逻辑视图（同一物理摄像头） |
| 退化 | illumination / defocus / sensor noise | illumination / motion blur / sensor noise |
| 评估集 | 完整 official test **2,468 条** | 完整 official test **12,322 条**（另保留 256 条 quick check） |
| 无标签语义 | refresh 480 条，CE 权重 0 | refresh 代表轨迹，CE 权重 0 |
| 评估的 Adapter 对照 | cloud-unlabeled、label-only、hybrid + illumination 专项 | cloud-unlabeled、label-only、hybrid |

## 结果对照

两个数据集的官方/独立评估口径（顶行 Edge baseline，粗体为正式 cloud-unlabeled 主结果）：

### ModelNet40（完整 official test，2,468 条）

| 方法 | Clean | Illumination | Defocus | Sensor noise | Mean drift |
|---|---:|---:|---:|---:|---:|
| Edge baseline | 96.759% | 89.141% | 88.412% | 84.400% | 87.318% |
| **Cloud unlabeled（8/12 clean-guard 最终版）** | **95.705%** | **92.301%** | **94.449%** | **92.990%** | **93.247%** |
| Label-only（有标签上界） | 96.313% | 90.032% | 94.692% | 93.152% | 92.625% |

无标签 Adapter 三漂移平均提升 **+5.929 pp**（illumination +3.160 / defocus +6.037 / noise
+8.590 pp），clean 代价 −1.053 pp。该版以更强的无标签 clean replay anchor 换回 0.324pp
clean，并避免了旧 6× illumination 过采样的过度偏置。

### BoxCars116k（完整 official test，12,322 条）

| 模型 | Clean | Illumination | Motion blur | Sensor noise | 漂移平均 |
|---|---:|---:|---:|---:|---:|
| Edge baseline | 88.04% | 74.03% | 77.57% | 71.77% | 74.46% |
| **Cloud unlabeled Adapter** | **88.09%** | **78.45%** | **79.51%** | **79.10%** | **79.02%** |
| Label-only（有标签上界，开发集 649 条口径） | 94.30% | 83.05% | 87.52% | 87.67% | 86.08% |

无标签 Adapter 三漂移平均提升 **+4.56 pp**，逐条件 paired-bootstrap 95% CI 全部不跨 0
（illumination [+3.95, +4.90]、blur [+1.57, +2.31]、noise [+6.77, +7.90]）；clean 基本持平
+0.06 pp（[-0.20, +0.31]）。

> 另保留固定 seed 的 256 条 class-stratified quick check（Edge 72.79% → 76.04%，+3.26 pp），
> 用于说明抽样方向与开发集一致；正式结论以上面全量表为准。

注意口径：BoxCars 的 label-only 数字来自 649 条开发集，完整 test 只评估了 Edge / cloud-unlabeled
两组模型（skip teacher 以省 6B 推理）；ModelNet40 的 label-only 与主结果同属于 2,468 条完整 test。
不要把两个数据集的 label-only 数字并列为一个平均值。

### 开发集上的两种对照含义

| 对照 | 结论 |
|---|---|
| label-only（有标签上界） | cloud-unlabeled 在 BoxCars 开发集只低 0.87 pp、在 ModelNet40 完整 test 低约 0.2 pp；无标签 refresh 接近有标签充分训练的收益 |
| hybrid（CE + teacher） | BoxCars 开发集比 label-only 低 0.41 pp → “在已有真实标签 CE 上叠加当前 KD/feature”无额外增益，保留为中性/负向消融 |

## 系统闭环与通信口径

```text
漂移检测 → 上传少量 representative / hard 四视图轨迹
  → 云端冻结 InternViT-6B 提取 task logits + visual features
  → 云端只训练 MV-ViT-S 的 AdaptFormer（约 0.3M 参数）
  → 下发 adapter-only checkpoint（实测 1,216,745 bytes，约 1.2 MB）
  → 边缘 MV-ViT-S + Adapter 低延迟恢复推理（断网时 u=0 本地自治）
```

- InternViT-6B、task head、cache、训练期 projector 永远留在云端，不进入边缘 forward，也不随
  adapter 下发。
- 边缘接收物与既有 `u=1` 接口兼容，回滚和弱网逻辑不变（见 `接口契约.md` / `网络波动模拟器设计.md`）。
- 两数据集的下发物均通过键与参数量审计：299,916 个 AdaptFormer 参数、约 1.2 MB，不含 backbone、
  norm、head 或 cloud projector。

## 证据边界（如实申报）

1. 两个数据集的官方/独立评估均为**完整 test**（ModelNet40 2,468 条、BoxCars 12,322 条）；
   BoxCars 另保留 256 条 class-stratified quick check 作为抽样方向说明。
2. 两类退化均为合成但已校准的相机退化（illumination / blur / defocus / sensor noise），真实
   摄像头时间序列应作为后续外部验证。
3. ModelNet40 最终版 clean 下降 1.053 pp、BoxCars 全量 test clean 基本持平（+0.06 pp），能力
   保持曲线按各自数值如实画。
4. task head 的离线标签成本、6B feature cache 时间属于云端准备成本，不是零成本在线学习。
5. 旧 Qwen3-VL condition / soft-label 路线为负向消融（BoxCars 消融结果见
   `local/archive/vlm_conditioned_20260809/`），不在当前主线，不恢复。
