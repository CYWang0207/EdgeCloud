## 这次结果的正确含义

- 本次 teacher 不是 VLM，而是已有 baseline 的预测 logits，只是为了先打通“离线 teacher → 蒸馏 → Adapter → 下发加载”链路。
- baseline 初始化时 student 与 teacher 相同，蒸馏项起初接近零；后续的小幅变化主要来自真实标签 CE、数据增强，以及可训练的 adapter/norm/head 继续适配。不能把约 0.46 个百分点的 validation 差异归因于 VLM。
- 真 VLM 到位后，应只替换软标签导出端并做独立 test、漂移集和多随机种子对照，才能判断 VLM 蒸馏是否真的提升。
- `adapter_best.pth` 不是独立模型；推理时必须先加载同一 baseline，再 `attach_adaptformer(r=32)`，最后加载 Adapter checkpoint。

## Prompt、Adapter 与重训练的区别

| 路径 | 当前代码实际输入/训练对象 | 用途 | 当前成熟度 |
|---|---|---|---|
| Visual Prompt | 漂移类型 ID 查表得到可学习的连续视觉 token；不是中文/英文文本 | 给冻结 ViT 一个轻量条件提示 | BoxCars 单批次链路已验证；没有接 VLM |
| Adapter 蒸馏 | teacher 的 16 类 logits；训练 adapter + norm + head | 把 teacher 的任务知识压进约 1.2 MB 增量权重 | baseline 占位 teacher 已完整实跑；真 VLM 未接 |
| 漂移重训练 | 带亮暗、模糊、噪声、遮挡等模拟漂移的有标签图片；训练整个 MV-ViT | 处理更严重或结构性的长期变化 | 脚本和单批次链路已有；尚未完成正式对比实验 |

当前调度叙事是 `u=0` 使用本地 baseline，`u=1` 同步小型 Adapter，`u=2` 使用漂移重训练模型。代码中仍保留旧 Prompt 回退路径，但主线已经切换为 Adapter。VLM Oracle、漂移触发后的在线闭环训练以及 `u=2` 的真实通信/训练成本仍需后续实现和测量，不能表述为已经完成。
